# LangChain Component: Tools & Tool Calling

Language models are limited to processing text and knowledge frozen in their training weights. They cannot natively calculate math equations reliably, check today's stock price, search the live web, or write to a SQL database.

**Tools** are executable functions that an LLM can invoke to interact with the outside world, perform calculations, query APIs, and take real-world actions.

---

## 1. What is a Tool in LangChain?

A LangChain Tool is composed of three elements:
1. **Name**: A clear identifier (e.g., `calculate_tax` or `search_web`).
2. **Description**: Natural language documentation explaining what the tool does and when the LLM should invoke it. (The LLM reads this description to decide whether to call the tool!).
3. **Args Schema**: A Pydantic schema or type hints specifying what arguments the function expects.
4. **Function**: The actual Python callable executed when requested.

---

## 2. Creating Custom Tools

### A. The `@tool` Decorator (Easiest & Most Popular)
You can turn any Python function into a LangChain tool simply by decorating it with `@tool` and providing docstrings with type hints:

```python
from langchain_core.tools import tool

@tool
def multiply_numbers(a: float, b: float) -> float:
    """Multiply two numbers together and return the exact product."""
    return a * b

@tool
def get_cricketer_stats(player_name: str) -> dict:
    """Fetch recent batting statistics for a given cricketer name."""
    # Simulated database lookup
    stats_db = {
        "virat kohli": {"matches": 292, "runs": 13906, "average": 58.18},
        "rohit sharma": {"matches": 265, "runs": 10866, "average": 49.16}
    }
    return stats_db.get(player_name.lower(), {"error": "Player not found"})

# Inspect the auto-generated tool metadata
print("Tool Name:", multiply_numbers.name)
print("Tool Description:", multiply_numbers.description)
print("Tool Args Schema:", multiply_numbers.args)
```

---

### B. `StructuredTool` with Explicit Pydantic Schemas
For complex tools with nested parameters and strict validations:

```python
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

class OrderLookupSchema(BaseModel):
    order_id: str = Field(description="The unique 6-digit alphanumeric order ID (e.g. ORD123)")
    customer_id: int = Field(description="The numeric customer account ID")

def lookup_order(order_id: str, customer_id: int) -> str:
    return f"Order {order_id} for Customer #{customer_id} is OUT FOR DELIVERY."

order_tool = StructuredTool.from_function(
    func=lookup_order,
    name="order_lookup",
    description="Check the delivery status of a customer order.",
    args_schema=OrderLookupSchema
)
```

## 3. Binding Tools to Models (Tool Calling)

Modern LLMs (GPT-4o, Claude 3.5, Gemini 1.5) support native tool calling. LangChain connects tools to models via `.bind_tools()`:

```python
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two integers together."""
    return a + b

model = ChatOpenAI(model="gpt-4o-mini")

# Bind the tool to the model
model_with_tools = model.bind_tools([add])

# Ask a query that requires the tool
response = model_with_tools.invoke("What is 4325 + 9812?")

# The model decides to call the tool!
print("Tool calls generated by LLM:")
print(response.tool_calls)
# Output: [{'name': 'add', 'args': {'a': 4325, 'b': 9812}, 'id': 'call_123...'}]
```

---

## 4. Executing the Tool and Returning `ToolMessage`

To complete the cycle, you execute the tool with the LLM's arguments and pass the output back via `ToolMessage`:

```python
from langchain_core.messages import HumanMessage, ToolMessage

query = "What is 4325 + 9812?"
messages = [HumanMessage(content=query)]

# 1. Model requests tool call
ai_msg = model_with_tools.invoke(messages)
messages.append(ai_msg)

# 2. Execute the tool locally
for tool_call in ai_msg.tool_calls:
    if tool_call["name"] == "add":
        tool_output = add.invoke(tool_call["args"])
        # 3. Create ToolMessage with matching tool_call_id
        messages.append(ToolMessage(
            content=str(tool_output),
            tool_call_id=tool_call["id"]
        ))

# 4. Pass results back to model for final natural language answer
final_response = model_with_tools.invoke(messages)
print("Final AI Answer:", final_response.content)
# Output: "4325 + 9812 is 14,137."
```

---

## 5. Summary & Best Practices

1. **Write Descriptive Docstrings**: The LLM chooses tools based exclusively on the description. If your docstring is vague (`"does stuff"`), the LLM won't know when or how to use it.
2. **Type Annotations**: Always include type hints (`a: int, b: str`) so LangChain can generate the corresponding JSON schema for the model.
3. **Error Handling**: Tools should return informative error strings rather than crashing, so the LLM can self-correct and retry.
