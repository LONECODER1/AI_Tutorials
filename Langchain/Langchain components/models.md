# LangChain Component: Models (LLMs & Chat Models)

Models are the foundational reasoning engines in LangChain. LangChain provides a standardized, unified interface to connect with dozens of model providers (OpenAI, Anthropic, Google Gemini, Ollama, Hugging Face, Mistral, Groq, etc.) without locking your codebase into a single vendor's API.

---

## 1. Core Model Types

LangChain distinguishes between two primary types of language models:

### A. Chat Models (Modern Standard)
- **Input**: A list of structured message objects (`SystemMessage`, `HumanMessage`, `AIMessage`, `ToolMessage`).
- **Output**: A structured `AIMessage` containing text content and optional tool/function call payloads.
- **Underlying Technology**: Modern instruction-tuned / conversational models (e.g., GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro, Llama 3).

### B. Traditional LLMs (Legacy / Text-In, Text-Out)
- **Input**: A raw string prompt.
- **Output**: A raw string response.
- **Underlying Technology**: Base completion models (e.g., `gpt-3.5-turbo-instruct`).

---

## 2. Message Types in Chat Models

Chat models consume structured dialogue through standard message classes:

| Message Class | Purpose | Example |
| :--- | :--- | :--- |
| `SystemMessage` | Instructs the model on its identity, tone, behavioral rules, and constraints. | `"You are an expert cricket analyst. Answer concisely."` |
| `HumanMessage` | The prompt or question coming from the user. | `"Who has the highest batting average in ODI cricket?"` |
| `AIMessage` | Responses generated by the assistant, which can include tool call requests. | `"Virat Kohli averages over 58 in ODI cricket."` |
| `ToolMessage` | Delivers the result of an executed external function/tool back to the model. | `"Tool execution result: {'runs': 13906, 'avg': 58.18}"` |

## 3. Practical Code Examples

### Example 1: Basic Invocation of a Chat Model

```python
from langchain_core.messages import SystemMessage, HumanMessage
from langchain_openai import ChatOpenAI
# Or from langchain_google_genai import ChatGoogleGenerativeAI
# Or from langchain_anthropic import ChatAnthropic

# 1. Initialize the model
model = ChatOpenAI(
    model="gpt-4o",
    temperature=0.7,
    max_tokens=500
)

# 2. Construct messages
messages = [
    SystemMessage(content="You are a helpful Python programming tutor."),
    HumanMessage(content="Explain Python list comprehensions in 2 sentences.")
]

# 3. Invoke the model
response = model.invoke(messages)

print("AI Response:")
print(response.content)
```

---

### Example 2: Streaming Responses in Real Time

Chat models support streaming tokens token-by-token as they are generated, improving user experience:

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

model = ChatOpenAI(model="gpt-4o-mini", streaming=True)

for chunk in model.stream([HumanMessage(content="Write a short haiku about coding.")]):
    print(chunk.content, end="", flush=True)
print()
```

---

### Example 3: Batch Processing

Process multiple queries concurrently with automated batching:

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini")

prompts = [
    "What is Python?",
    "What is JavaScript?",
    "What is Rust?"
]

responses = model.batch(prompts)
for p, r in zip(prompts, responses):
    print(f"Q: {p}\nA: {r.content[:80]}...\n")
```

### Example 4: Switching Between Model Providers (Model Agnostic)

One of LangChain's biggest advantages is the ability to swap models with a single line:

```python
import os

# Option A: OpenAI
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-4o")

# Option B: Google Gemini
# from langchain_google_genai import ChatGoogleGenerativeAI
# llm = ChatGoogleGenerativeAI(model="gemini-1.5-pro")

# Option C: Local open-source model via Ollama
# from langchain_community.chat_models import ChatOllama
# llm = ChatOllama(model="llama3.1")

# The rest of your application code remains 100% identical:
response = llm.invoke("What are the advantages of model-agnostic code?")
print(response.content)
```

## 4. Key Parameters & Best Practices

1. **`temperature` (0.0 to 2.0)**:
   - `0.0`: Deterministic, factual, ideal for coding, data extraction, and mathematical reasoning.
   - `0.7 - 1.0`: Balanced creativity, ideal for general conversation and content generation.
2. **`model_kwargs`**: Allows passing provider-specific parameters (e.g., `seed`, `top_p`, `frequency_penalty`).
3. **Always use Chat Models (`ChatOpenAI`, `ChatAnthropic`, etc.)** rather than legacy LLMs (`OpenAI`) for new projects, as major providers optimize features like JSON mode and tool calling specifically for chat models.
