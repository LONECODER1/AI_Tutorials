# LangChain Component: Output Parsers

Language models naturally generate free-form, unstructured strings. However, downstream software applications require structured data types—such as Python dictionaries, JSON objects, lists, or strongly-typed Pydantic classes. 

**Output Parsers** take the raw text or `AIMessage` output from a model and transform it into a structured, validated, and programmatically usable format.

---

## 1. Why Use Output Parsers?

- **Type Safety**: Guarantee that outputs adhere to specific data types (int, float, date, list).
- **Format Instructions**: Output parsers automatically inject schema instructions and formatting prompts into the LLM request.
- **Fail-Safe Parsing**: Handle parsing errors gracefully or trigger auto-fixing chains.
- **Seamless LCEL Integration**: Pipe directly after models: `chain = prompt | model | parser`.

---

## 2. Common Output Parsers

### A. `StrOutputParser` (Basic String Extraction)
Extracts the raw string `content` attribute from an `AIMessage`. This is the most frequently used parser for standard text-generation chains.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = ChatOpenAI(model="gpt-4o-mini")
prompt = ChatPromptTemplate.from_template("Tell me a one-line joke about {topic}.")

# Without StrOutputParser, output is an AIMessage(content="...")
# With StrOutputParser, output is a clean Python str: "..."
chain = prompt | model | StrOutputParser()

result = chain.invoke({"topic": "databases"})
print(type(result))  # <class 'str'>
print(result)
```

---

### B. `JsonOutputParser` (Structured JSON Parsing)
Instructs the model to return valid JSON and parses the output directly into a Python dictionary.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser
from pydantic import BaseModel, Field

# Define expected data structure
class CricketerProfile(BaseModel):
    name: str = Field(description="Name of the cricketer")
    country: str = Field(description="Country represented")
    role: str = Field(description="Batting/Bowling/All-rounder role")
    notable_records: list[str] = Field(description="List of top 2 records")

parser = JsonOutputParser(pydantic_object=CricketerProfile)

prompt = ChatPromptTemplate.from_messages([
    ("system", "You extract factual cricket profiles. {format_instructions}"),
    ("human", "Extract profile for: {player_name}")
])

# Inject format instructions automatically generated by parser
prompt_with_instructions = prompt.partial(
    format_instructions=parser.get_format_instructions()
)

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
chain = prompt_with_instructions | model | parser

result = chain.invoke({"player_name": "Virat Kohli"})
print(type(result))  # <class 'dict'>
print(result)
# Output: {'name': 'Virat Kohli', 'country': 'India', 'role': 'Top-order batsman', 'notable_records': [...]}
```

---

### C. `PydanticOutputParser` (Strict Schema Validation)
Returns a typed Pydantic instance rather than a plain dictionary. If the LLM generates fields missing mandatory validation rules, Pydantic raises an error.

```python
from langchain_core.output_parsers import PydanticOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class MovieReview(BaseModel):
    title: str = Field(description="Title of the movie")
    release_year: int = Field(description="Year of release")
    sentiment: str = Field(description="Sentiment: Positive, Neutral, or Negative")
    summary: str = Field(description="Two-sentence summary of the review")

parser = PydanticOutputParser(pydantic_object=MovieReview)

prompt = PromptTemplate(
    template="Analyze this review:\n{review}\n\n{format_instructions}",
    input_variables=["review"],
    partial_variables={"format_instructions": parser.get_format_instructions()}
)

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
chain = prompt | model | parser

review_text = "Inception (2010) blew my mind with its multi-layered dream world. Nolan delivered a masterpiece."
result: MovieReview = chain.invoke({"review": review_text})

print(f"Title: {result.title}")
print(f"Year: {result.release_year}")
print(f"Sentiment: {result.sentiment}")
```

---

### D. Modern Alternative: `model.with_structured_output()` (Recommended)
Modern chat models (OpenAI, Anthropic, Gemini, Mistral) feature native tool-calling / JSON schema modes. LangChain provides `.with_structured_output()`, which is more reliable than text-based parsers because the schema is enforced at the API level.

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

class WeatherReport(BaseModel):
    location: str = Field(description="City or region name")
    temperature_c: float = Field(description="Temperature in Celsius")
    conditions: str = Field(description="Sunny, Rainy, Cloudy, etc.")

model = ChatOpenAI(model="gpt-4o-mini")

# Bind the Pydantic schema natively
structured_model = model.with_structured_output(WeatherReport)

result = structured_model.invoke("It is currently 22 degrees and sunny in Mumbai.")
print(result.location)       # "Mumbai"
print(result.temperature_c)   # 22.0
print(result.conditions)      # "Sunny"
```

---

## 3. Comparison of Approaches

| Approach | Best For | Pros | Cons |
| :--- | :--- | :--- | :--- |
| `StrOutputParser` | Text generation, chatbots, essays. | Fast, universal, zero overhead. | Returns unvalidated string. |
| `JsonOutputParser` | Dynamic JSON outputs without strict typing. | Flexible, works on most open models. | Susceptible to occasional JSON syntax errors on weaker models. |
| `PydanticOutputParser` | Validated objects with custom field validators. | Full Python class with IDE autocompletion. | Requires model to strictly adhere to instructions in prompt. |
| `.with_structured_output()` | Enterprise production systems. | Highest reliability, uses native function calling. | Requires modern chat models with function-calling support. |
